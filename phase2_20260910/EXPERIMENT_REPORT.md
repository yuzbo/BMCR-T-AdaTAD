# H65 思想复现与 BMCR-T：完整实验报告

发布说明：以下描述原完整实验。Git仓库提供源码、日志、全部压缩预测和指标；原视频与大型权重仍保留在原独立实验目录，未打包进入本公开副本。资源路径已匿名化，数值未改写，发布适配见[说明](../docs/PUBLICATION_NOTES.md)。

实验已完成：四个新模型均完成60轮训练，官方AdaTAD与H65-C、BMCR-T在VideoMAE-S/B上的六组评测均覆盖全部211条测试视频、792个滑动窗口。官方基线仅复用现有权重测试，没有重新完整训练。

本轮实现将矩阵/卷积MAC减少约48.45%（S）与49.55%（B），但四个新模型的平均mAP均低于各自官方基线，本次固定窗口计时也没有显示推理加速。计算量降低与实际速度收益需要分别判断。

BMCR-T相对H65-C的平均mAP在S/B上分别增加0.30/0.73个百分点，仍分别低于官方5.86/3.79个百分点。S的mAP@0.5由H65-C的66.33%降为BMCR-T的65.91%；B由69.93%升为70.67%。这些是单次训练结果，不据此宣称稳定或显著收益。

H65-C保留H65的时序采样、直通梯度和分类/定位贡献监督，将768个候选位置中的384个位置送入重骨干。BMCR-T使用相同核心、帧预算和训练日程，增加候选及互换伙伴的条件特征，并用EMA教师测量的带符号分类/真实时间定位效用替换贡献分布监督。在联合训练的反馈预热结束后，它每8次更新尝试可行交换监督；没有可行伙伴时不生成交换标签，测试阶段不使用GT选帧。

预热采用均匀K384采样，同时训练Adapter、检测器和低分辨率CNN+ASFormer的辅助任务。随后40轮逐步启用学习采样及检测器反馈。VideoMAE除Adapter外保持冻结；冻结参数本身不被计作跳过计算。所选帧序列按对应坐标训练，预测在NMS之前回映真实时间；保留官方全视频汇总和逐类别SoftNMS。

本轮是基于纯净官方全局TIA核心的H65-C-60实验，不是历史90轮H65配置的数值复刻。重骨干实际执行由48个16帧片段降到24个，并保持单个视频内的全局时间交互。

新模型从K400识别预训练开始，检测器与Adapter不从已有TAD权重初始化。全部200条训练视频每轮参与一次标准随机窗口训练，batch2、每轮100次更新；20轮公共预热与40轮联合训练分别为2000与4000次成功更新。每个骨干的公共预热只实际训练一次，两种方法都从该预热终点EMA初始化并重置优化器/调度器。新模型主结果统一采用最后一轮EMA，没有根据测试集选轮次或调整超参数。

全部六个训练阶段共记录20000次实际优化器更新，累计训练阶段耗时折合21.22 GPU小时。该数值将共享预热每骨干只计一次，不含排队、预检、审计和测试，不是计费账单。每个方法概念上的完整周期均为60轮。详见[训练汇总](TRAINING_SUMMARY.md)。

官方基线使用资源交接中指定的固定检查点，S/B保存的epoch字段分别为59/51，均严格加载state_dict_ema。本轮未重训或依据本轮测试挑选官方权重；epoch字段不能用于推断原始总训练长度。官方与新方法的训练日程/目标不同，因此这组比较不能被解释为仅改变采样器的单变量消融。

计算量来自实际前向算子的形状计数，包括融合FlashAttention中的QK与AV矩阵乘法。每项主比较均使用同一完整768候选窗口：video_test_0000007，起始帧0，固定测试顺序index2；另外记录首个503有效候选的部分填充窗口及253候选短窗口。固定物理执行预算令这三类窗口的MAC相同，实际路由处理及耗时仍可不同。

FLOPs按矩阵/卷积2MAC定义，未包括逐元素算术、归一化和融合softmax等全部操作。MAC不能代替实际时延、吞吐或能耗，也没有据此宣称节能收益。

时延条件为RTX4090独立作业、BF16骨干/scout与FP32检测器、batch1、输入已在GPU，5次预热后保留全部20次CUDA同步计时。范围含scout/路由、骨干、Adapter、检测器和NMS前坐标回映，不含视频读取/解码及NMS；这是指定窗口的模型时延，不是全测试集平均时延。不同作业可能使用不同节点或GPU；均值与中位数同时保留，H65-S包含一个204.56ms长耗时样本。没有测量组件分段耗时，因此不把额外时间定量归因于某个模块。

两种骨干都完成了训练集上的128窗口交换审计：各产生390次可测交换，310次用于拟合/缩放、80次来自15个实际留出训练视频。原贡献代理在留出交换上的分类/定位Spearman分别为S的-0.030/-0.028和B的0.126/-0.203，排序信号较弱且不一致。审计未使用测试视频；重复GT计数不是独立实例数。这些诊断支持谨慎解释贡献代理，不单独证明BMCR最终收益。

所有新训练均核验了连续更新、完整轮次和末轮EMA；六项测试的211视频范围、五阈值均值、计数分量与计时记录已核验，未解析矩阵算子列表为空。本地上游Git工作区保持干净；远端是不带.git的导出副本，其369个模型/数据/评测源码和配置文件与该干净提交逐字节一致，没有改动上游源码。详见[最终验证记录](FINAL_VALIDATION.json)与[源码比对](UPSTREAM_SOURCE_VERIFICATION.json)。

本轮结论是思想复现和完整比较已经完成，但当前实现尚不足以支持在本次条件下替换官方AdaTAD来同时获得精度与速度收益。若继续研究，优先应做组件分段计时、固定权重下的推理实现优化，以及与K384均匀采样的预算匹配控制比较；这些额外结果本轮未生成，也不据现有表格推断其结论。

实现位于h65/full；训练、审计、评测和调度入口分别为tools/full_train.py、full_audit.py、full_eval.py、full_dispatch.py。所有代码、日志、预测、报告及模型权重均保留在独立项目内，共享环境、数据及已有权重仅被只读复用。各模型执行完成记录和证据位于runs对应目录。历史失败尝试和初始未完整计数的profile已保留，最终表只使用修正后的结果。
