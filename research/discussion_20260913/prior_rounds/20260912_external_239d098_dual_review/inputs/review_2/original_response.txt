**我的选择是：先完成同配方修正 BMCR，把已有高分模型保留为真实锚点；随后用同一 D1 checkpoint 拆开“选点、缺失位置填充、EMA”三个因素，并优先验证具有稳定初值的 C2 校准。长期最值得投入的架构，是保留全时间低成本视觉状态与 global-TIA，条件执行昂贵的 attention、FFN 和深层残差，而不是直接把更多位置交给新初始化的最终特征预测器。**

现有证据**没有排除完整 clip**；同样，也**没有证明继续训练 D1 或增加蒸馏必然恢复精度**。真正需要解决的是：在给定观察、时间几何和已有状态的条件下，哪一次额外计算能改善实际检测，而不仅是降低某种特征误差。

# （a）现状判断：哪些可靠，哪些仍未解决

## 1. 已有成果应当保留，但不能扩大其含义

| 骨干 | 官方 AdaTAD | 旧 H65-C，60轮 | 旧 BMCR-T，60轮 |                     修正 H65 |
| -- | --------: | ----------: | -----------: | -------------------------: |
| S  |  69.0126% |    62.8593% |     63.1563% |          63.4094%，60轮峰值／终点 |
| B  |  71.1280% |    66.6128% |     67.3404% | 67.1328%，55轮峰值；60轮66.9026% |

因此，准确的判断是：**已完成新模型 B 路线中旧 BMCR 最高；S 上修正 H65 高于旧 BMCR；官方仍高于两者。** 旧 BMCR 对旧 H65 的平均增益只有 S +0.2970pp、B +0.7276pp，且 S 的 @0.5/@0.7 下降。它是值得继承的成果，却还不是“各阈值稳定保精度”的证据。

修正 BMCR 尚未开始，不能填写新分数。当前代码修复不能追溯改变 `15280e5` 旧配方训练出的权重；历史 S65.385724% 也不能移植到 local-TIA8 的实验账本。修正 warm、旧高分模型、修正 H65 峰值与终点应分别保存，而不是把后来一个新模型自动视为替代品。

## 2. Z0 曲线没有判完整 clip“死刑”

| S 路线        | 完整测试平均 mAP | 证据含义                  |
| ----------- | ---------: | --------------------- |
| D768G       |   69.0126% | 官方 global-TIA384 密集参考 |
| D768L       |   67.5344% | 同权重变 local-TIA8；仍全部计算 |
| Z16         |   43.2835% | 零新增训练，均匀完整 clip＋插值    |
| Z24         |   56.1065% | 零新增训练；不是训练24轮         |
| Z36         |   62.5804% | 同类预算探针                |

| T24A，第5轮EMA |   50.6458% | 500次辅助更新后的早期结果        |

快照中 S D1 是 **15/80轮、1500/8000更新**；第10轮全测试仍运行。`RESULTS.md` 的进度文字更早，不能拿它覆盖最新机器快照。

这些结果支持三个有限结论：

* 在当前固定 local 权重和插值接口下，增加重观察有益。
* 当前均匀24优于当前随机24约 **3.1043pp**，说明覆盖结构值得研究。
* global→local 已先损失 **1.4781pp**；local→Z24 再损失 **11.4279pp**。

它们没有控制训练适配、补全模型、全局上下文、采样单元和检测表示，因而不能把后一个差值全部归给“完整 clip 粒度”。也不能把三个预算点直接解释成信息丢失、优化失配和几何失配各占多少。

**可证伪预测：** 若主要问题是混合表示失配，固定 U24、保留相同重特征，只改变初始化和学生图校准，就应改善相关检测误差；若失败集中在完全未观察、廉价状态也无法辨认的短事件，则应增加可观测性或改选择层级，而不是继续只延长训练。

## 3. 三种时间合同必须分开

| 路线       | 重骨干组织         | native | 检测轴                   | TIA       |
| -------- | ------------- | ------ | --------------------- | --------- |
| 官方       | 原48×16候选      | 384    | 原768                  | global384 |
| H65/BMCR | K384重新拼成24×16 | 192    | selected-rank384，输出回映 | global192 |
| DS3-L    | 保留原clip身份     | 恢复原384 | 原768                  | local8    |

这里“16帧 clip”指16个候选观察；候选 stride=4，不是16张连续原视频帧。

另一个重要修正是：**global-TIA 不是全视频全连接 temporal attention。** 当前 Adapter 把各 clip 的时间 tubelet 接起来，对同一空间格点做低维 kernel-3 时间卷积及 pointwise 卷积。local8 切断的是跨 clip 的时间传播；attention 本身仍在 clip 内。这个变化可以降低精度而不减少 FLOPs。源码定位为 `vit_adapter.py::Adapter`，19–75行。

rank 回映放在 NMS 前是正确的，但**端点坐标可逆不等于检测合同等价**。rank 域的邻接、动作长度、中心采样半径、金字塔回归范围仍然改变。严格加载、通道相同，也不能证明 rank384 detector 与 original768 detector 语义兼容。

## 4. 已经正确的部分，不应重新列成当前 bug

当前 LR 参数分组和裁剪伪端点处理已经修复；BMCR 的定位代价保留漏检惩罚；DS3 的 clip 和后四层重 MLP 确有压紧执行；计数器包含融合 attention 的 QK/AV。这些应保留。冻结参数不是跳算，但当前 DS3 也并非只有冻结而没有条件执行。

**本次没有找到能够独立解释全部掉点的新增致命运行错误。** 更重要的缺口属于以下两种监督合同。

### BMCR：S0 的单交换标签，未必适用于 S1 的重新解码

`h65/full/model.py::route`，45–57行，先得到 S0，再将条件效用加回基础分数，重新采样得到 S1；`train_batch` 的反事实监督却针对 S0 附近的一次交换。

真实重编码、交换方向和漏检处理是可靠基础，但单交换收益不保证多个同时变化后的收益。重新求容量阈值、平滑和系统采样可能移动多个点，伙伴和 clip 组装也会改变。

此外，分类交换标签固定 S0 的目标指派，而定位重新匹配；这是有理由的设计，但不是实际 rank 检测训练损失的完全同义替代。分类／定位标准化尺度、阈值和 cap 都需要在修正 warm 后重新审计。

建议增加三种训练集审计，而不是先扩大效用头：

$$
S_0\rightarrow\text{单交换},\qquad
S_0\rightarrow\text{实际 }S_1,\qquad
S_1\rightarrow\text{单交换}.
$$

若第一种预测好、第二种经常变坏，应限制一步变化数量或重新建模组合效用，而不是继续把局部标签解释为全局决策收益。

### DS3：dense fitting 不等于实际混合学生检测学习

当前 D1 的梯度标签近似为：

$$
\sum\left|\nabla_{F_T}\ell_T\odot(F_T-\hat F)\right|.
$$

它是 teacher 状态上的非负敏感度代理，不是混合学生状态上的有符号损失改善。当前也没有实际混合稀疏学生图的 GT 检测损失训练。

还有一个动作定义问题：head0 学的是 H0→最终深层的价值，DAD 首阶段需要的却是“谁值得先进入8层”；**0→12 与0→8不能自动视为相同条件效用。** 后四层近似器在 dense 输入上拟合，推理时却递归接收被前面近似改变的输入，这也需要单独校准。

尤其要避免错误归因：**T24A只使用H0与24个完整12层clip，不使用H8或稀疏MLP。** 第5轮低分不能判后两者失败。

## 5. EMA 与初始化需要分开检查

H0 有预训练的视觉部分，但新增投影、输出和路由并不保证初值等于 Z24 插值；H8 的“残差形式”也不等于初值已经匹配最终深层特征。

独立计算得到：

$$
0.999^{500}=0.6063789,\qquad
\text{EMA半衰期}\approx692.8\text{更新}.
$$

这是**参数初值系数**，不是输出或 mAP 比例。应比较 online/EMA 在相同选点上的补全质量，再比较路由；低早期分数不能全部归因于 EMA。现有 `load_aux(..., ema=False)` 已提供 online 读取基础。

CPU 检验还确认：当前覆盖锚点加 stable top-k，在零 logits 时得到 `[0..20,28,38,47]`，**不是均匀24**。这不是对已训练路由的测量，而是对“零初始化自动产生均匀先验”的反例。数值和脚本见[机制检验结果](sandbox:/mnt/data/bmcr_review/mechanism_checks.json)。

## 6. 冗余应定义为条件任务收益，而非相似度

建议统一建模为：

$$
\Delta U(a\mid s)
=
\mathbb E[
\ell_{\rm TAD}(D(s),Y)
-
\ell_{\rm TAD}(D(T_a(s)),Y)
\mid s],
$$

其中动作 \(a\) 是某段时间、某个空间区域或某次深度升级；状态 \(s\) 包含已有轻／重特征、物理时间、有效观察、覆盖和不确定性。决策同时考虑 \(\Delta U\)、实际增量成本和覆盖约束。

帧效用一般不能直接相加为 clip 效用：两帧可能联合才显示运动方向，也可能重复提供同一证据。低梯度也不意味着可删除——例如 \(L(f)=(f^2-1)^2\)，teacher 在 \(f=1\) 处梯度为零，替换成 \(f=0\) 却使损失增加1。上述反例已做 CPU 检验，但不被用来定量解释真实 mAP 损失。

**可保证的只有条件明确的部分：** 全预算同算子执行可验证函数等价；有限数据上可验证经验前沿。少观察对任意视频无条件保持性能不能保证：若两个视频只在被删区间存在不同事件，保留观察完全相同，学生就无法区分。局部损失或特征误差界也不能直接变成 mAP 保证，除非同时控制排序、tIoU、匹配和 NMS 的翻转边界。

# （b）跨领域机制：真正值得迁移什么

完整报告逐项给出了原任务、监督、计算位置、状态与失败方式。最关键的联系如下。

| 同类科学问题                   | 原机制及证据                                                      | 对 TAD 的迁移条件与反面证据                                                        |
| ------------------------ | ----------------------------------------------------------- | ----------------------------------------------------------------------- |
| 不必处处高成本观察，但不能失去新事件       | AdaFocus V2 的全局低成本观察＋局部重计算；SlowFast 的多速率信息路径                | 借鉴全时间便宜状态与局部细化；不能照搬视频分类的整体早退，后续同类动作仍需被发现。([arXiv][1])                   |
| 密集输出中的位置可以少算几层，但退出后要留下状态 | DToP 保留退出预测与类别上下文；TR-BERT 保留退出 token 表示以支持原位置输出             | TAD需要保留时间位置、退出状态和事件覆盖；“背景容易”不等于其对动作起点没有上下文价值。两者都不是纯D1的成功证据。([arXiv][2]) |
| 所有位置轻算，少数位置重算            | CoLT5 的轻重路径，以及分开的重 query、K/V、FFN路由                          | “需要被更新”与“需要提供上下文”应分开；但CoLT5经过条件计算预训练，不能据此推断200视频足以从弱初始化恢复。([arXiv][3])  |
| 训练与推理调度不同，何时仍合理          | PointRend的采样训练/迭代细化；QueryDet的密集状态与稀疏查询头                     | 若推理得到同样局部状态和必要邻域，异构未必有害；但二者不能证明先删RGB也安全，粗查询漏掉的目标无法被细化。                  |
| 不规则采样怎样保留覆盖与细节           | RandLA-Net的随机采样＋几何聚合；3DSSD的几何/特征融合采样                        | 先聚合、再少算，比先盲删证据更合理；均匀时间覆盖与任务前景效用互补，任何一项都不能独立保证事件保留。([arXiv][4])          |
| 重复重算能否换成状态更新             | Deep Feature Flow的传播；Eventful Transformers的gate/buffer与增量更新 | 缓存必须带上下文、位置、年龄和失配条件；遮挡、新目标、clip相位与global-TIA窗口差异使跨窗缓存不免费。([arXiv][5])   |

### 对本项目最直接的新参照是 DyT，而不是再加一种通用蒸馏

DyT 的训练方式是：**完整计算 block，但对进入学生后续状态的重残差做 mask；全 token 仍有轻 adapter 路径。** 这说明“保留完整观察与主干计算”并不排斥“辅助学生见过推理时的缺失更新”。它更接近这里应研究的 C2，而不是当前 D1 的最终特征拟合。([arXiv][6])

但需要独立核对算子语义。我的 CPU 检验显示，同输入的逐 token MLP，dense-mask 与 gather/scatter 等价；attention 若训练保留全 K/V、推理删 K/V，就不等价。作者固定提交 `d1744f0...` 的已读分割 `Block.forward` 也确实是全 MLP 后乘 mask，**该函数没有可见的 compact eval 分支**。因此借鉴训练机制，并不意味着可以省略本项目的实际执行计数验证。

同时也存在反对“一切稀疏推理都必须重新训练”的证据：*Expediting Large-Scale Vision Transformer for Dense Prediction without Fine-tuning* 在已有浅特征上聚类、精炼并重建密集状态。其关键是**先有可用细粒度状态与重建关系**，而不是未观察位置凭空恢复。([arXiv][7])

ETAD则提醒另一条边界：完整前向、部分梯度反传和训练 proposal 采样可以提高训练效率，但不能作为少 RGB 推理保持 TAD 精度的证据。([arXiv][8])

# （c）收敛后的三条优先模型族

## 模型族 I：保留 BMCR/H65 合同的渐进压缩

**底座与初始化。** 修正 BMCR 完成后与旧 BMCR、修正 H65 分别保留，不预设新者必胜。在所选底座内保持 K384、native192、global-TIA192、rank384 detector。新增重计算门初始全开，因此先回到已有锚点，而不是换成弱 H0 的混合输出。

**训练图。** 先精确向量化 `FormalScout.condition`，不改伙伴与 tie；再在相同状态合同中做 C2 的晚层 FFN／深层重残差缺失训练。保留 GT 检测、合法边界和重新校准的条件效用；需要官方教师时，在原时间预测端对齐，不直接逐 index 对齐 rank 与 original 特征。

**推理图。** scout→S0→受控S1→K384观察→原骨干格点→条件贵算子→scatter完整native192空间状态→global-TIA192→rank检测→NMS前回映。当前实现的基础接口位于 `full/model.py::route/encode/predictions`。

**验证重点。** 精确向量化若改变选点或预测，就是实现不等价；不是新算法收益。若单交换效用好但 S1 变坏，先限制组合变化。若晚层低秩误差下降而定位仍坏，不继续默认扩大低秩模块可以解决。

这条路线最保守，但最尊重已有成绩。它也允许经验证后删除无益旧模块，而不是强制保留 BMCR 的全部结构。

## 模型族 II：原 clip 身份＋Z24稳定底座＋残差补全

这是我建议最先做的**新模型判别原型**。

固定 U24，使用现有 Z24 的重特征与物理中心插值形成 \(F_{\rm base}\)，然后只在未重算位置学习残差：

$$
F_{\rm student}
=
F_{\rm base}+(1-M_{\rm heavy})\odot
R_\phi(F_{\rm base},H_{\rm preview},\Delta t,\text{source},\text{valid}).
$$

将 \(R_\phi\) 的末层置零。这样初始函数可回到 **Z24**，而不是直接用新初始化 H0 覆盖缺失位置。上游网络不必全零；首步上游梯度暂为零也不自动构成错误。若仍执行 preview，初始函数等价不代表成本等价。

**训练图。** 冻结 local teacher 和检测器，完整算一次48 clips，缓存原 clip 的 H8/H12，构造实际预算的混合 native384；在该学生状态上跑真实 GT 检测损失。检测器参数冻结，但学生输入梯度必须保留。先固定 U24，后学习路由。

这里缓存成立的条件很严格：local-TIA8、原 clip 身份与相位、相同预处理和 padding、eval且无随机／batch耦合。它不适用于 global-TIA 的独立 clip 标签，也不能用 dense 后层缓存替代已改变输入的递归近似路径。

**监督迁移。** local teacher提供同构native特征；官方global teacher提供真实时间预测；BMCR/H65提供动作／边界／覆盖先验，clip和depth效用重新标定。当前检测头是独立 sigmoid 类别分数和左右距离回归：分类蒸馏应匹配 Bernoulli 语义，定位匹配物理端点或同构点距离，不能套互斥 softmax KL 或不存在的分布回归 KL。

**推理图。** 全时间廉价preview→固定／受覆盖约束的route→真实compact local clips→插值底座→缺失位置残差→原detector768。没有推理dense teacher。

这条路线只能承诺小预算初值回到Z24，**不能承诺24clip初值精确等于官方或BMCR**。H8零残差也只等于H8输入，不等于H12输出。

## 模型族 III：全时间空间状态＋条件重残差，保留 global-TIA

这是长期最有潜力、但实施风险也更高的路线。

**状态。** 全部768候选经过原Conv3D patch embedding，保持：

$$
[B,48,8,10,10,C].
$$

以完整原clip决定重attention／深度，以tubelet内空间token决定重FFN。未被重算的位置保留已有状态，而不是丢失或由随机最终特征替换；每层scatter回完整空间格后继续global-TIA384，最后仍走native384→原detector768。

**关键实现。** 原Block必须拆成attention残差、MLP残差、TIA三个阶段，保持顺序。不能给compact clip简单换一个`temporal_size`。原TIA在空间池化前有非线性投影，因此仅缓存池化native384也不能重现它。

**训练图。** 先做全重门的官方恒等测试，再逐步做C2：所有观察和贵算子仍可完整计算，但学生后续状态按预算缺失部分重更新，使用实际混合GT损失。global多层输入随学生状态变化，不能用固定dense teacher cache廉价代替下一层，可能需要teacher与学生双流。必要时再进入明确标注的J3。

**空间与深度。** 初版只稀疏FFN，保留完整attention邻接；之后再研究“选query、保留全K/V”或局部聚合重建。停止某位置后四层贵残差，不必停止其廉价时间上下文更新。分辨率或token merging路径必须在TIA前恢复公共格点。

**初始化限制。** 全重门可回到官方函数；立即减少一半贵更新后就不再精确等价，必须训练和验证。不能用推理先算dense再mask来制造“基线等价且省算”。

三条路线构成连续链：**BMCR/H65保留成绩与任务先验；模型族II验证原坐标混合状态和条件效用；模型族III再把“是否观察”与“是否继续重算”分开。**

# （d）最小判别实验顺序

| 顺序 | 最小干预                                                         | 能区分什么           | 不应同时改变什么                 |
| -- | ------------------------------------------------------------ | --------------- | ------------------------ |
| E0 | 修正warm20→重审效用尺度→BMCR joint40→完整测试                            | 修复配方下BMCR是否仍有增益 | 不加新路由、teacher、时间轴或稀疏模块   |
| E1 | 同checkpoint四格：I(U24)、H0(U24)、I(A24)、H0(A24)；再固定选点比online/EMA | 选点、填充、EMA分别贡献什么 | 全部24完整clip、12层、spatial=1 |
| E2 | 固定U24，零残差初始化；D1 fitting对比C2 mixed GT                         | 弱初始化与学生图失配      | 先不同时换global teacher和粒度   |
| E3 | 首先比较16候选clip与8候选micro-clip                                   | 决策绑定粒度是否重要      | 尽量固定权重、历史、原检测轴、TIA、浅状态   |
| E4 | 全局空间状态全重恒等→固定半重C2；再加一种空间或深度策略                                | 完整轻状态能否保护边界与短事件 | 不做全部因素的笛卡尔积              |

E1使用已有接口即可扩展；E2–E4是建议，不是已经完成的实验。80轮终局、60→80收益及当前online模型质量都需要真实后续结果，不能提前推断。

### 粒度控制必须承认不可完全匹配的因素

先在**全量patch embedding的原格点状态**上改变重更新分组，可以尽量固定tubelet相位、浅观察和检测合同。之后再研究真实RGB删除。后者会改变attention上下文或输入组装，不能声称只改变粒度。

应分别做“相同有效观察数”和“相同实际FLOPs”的比较；不同attention邻域下，一般不能同时固定两者。完整clip、重叠clip、自适应长短段还要计重复计算和padding，不能只报告唯一帧数。

### 评价不能只看平均mAP

保留五阈值mAP、逐类AP，同时观察短动作、合法起止误差、同类重复事件的合并／漏检、pre/post-NMS变化、置信度排序，以及GT内部和起止附近的重／轻覆盖、最大时间空洞。多主体、小物体、遮挡可做定义清楚的人工错误审查，不能假装现有标注已经支持完整自动分层。

单种子不能估计训练方差。固定checkpoint可按视频做成对bootstrap并重算整体AP，但不能消除**测试峰值选模**的乐观偏差；峰值、终点和测试轨迹应一起披露。后续多种子或更严格验证值得建议，但不增加强制160/40或任意1pp门槛。当前测试选模规则见实施记录。

# （e）算量、真实执行与系统成本

## 1. 独立核算：该压缩的主要不是TIA

对S，\(N=800,C=384,d=96\)。每clip每层：

$$
C_{\rm attn}=4NC^2+2N^2C,\quad
C_{\rm FFN}=8NC^2,\quad
C_{\rm TIA}=N(2Cd+d^2+3d).
$$

其中attention包含QK/AV。与原配置、算子结构及记录对照，独立公式得到：

| MAC组件           |        S，GMAC |        B，GMAC |
| --------------- | ------------: | ------------: |
| Patch embedding |       22.6492 |       45.2985 |
| Attention投影     |      271.7909 |     1087.1636 |
| QK/AV           |      283.1155 |      566.2310 |
| FFN             |      543.5818 |     2174.3272 |
| TIA             |       38.3533 |      153.1478 |
| Projection＋head |       14.4563 |       14.9092 |
| **总计**          | **1173.9470** | **4041.0774** |

按2MAC，分别为2347.8940和8082.1547 GFLOPs。这是矩阵／卷积算量，不含所有逐元素操作与内存搬运。

S的TIA占总量 **3.2670%**。仅后四层MLP保留75%／50%，新增模块之前最多省 **3.8586%／7.7173%**；D8全时间未加出口前约 **67.7202%**；160→128约 **58.8869%**。这些是算子估算，不是精度或时延实测。

模型族III保留全量patch、TIA和detector，仅一半clips执行各层昂贵attention/FFN，算术上约 **53.21%**；前两层全重、后十层半重约 **61.01%**，仍未计新增模块。它说明有研究空间，不构成性能承诺。数值均在交付的CPU脚本中可重算。

**三维保留率不能相乘。** 已经8层退出的位置没有后四层MLP可再节省；空间稀疏只作用于进入该层的active状态；preview、全时间TIA、重建和detector又不按相同比例下降。

## 2. 当前时延结论只能限定在当前scope

本轮Z24模型均值约42.60ms，官方约67.87ms，均值比约1.59×；但完整数据流程1229.65秒与1236.41秒接近，缓存和运行波动未控制。不能写成端到端1.59×加速，也不能替换旧官方51.21ms来计算新速度比。

下一轮应分别记录：

* 准备好输入与route后的GPU骨干。
* GPU常驻原输入到模型输出，含preview、路由、gather/scatter、重建与head。
* 解码、CPU预处理、H2D、窗口／视频NMS及完整elapsed。

每层同时记录实际clip、query、K/V、重MLP token、轻路径token数。保留均值、中位、p95和波动；现有20次计时不足以让尾部估计很稳定。当前全量RGB已解码，少算骨干不能据此声称省去解码成本。

## 3. teacher与缓存不能免费

local最终native缓存很便宜，但global-TIA需要完整空间状态。单个batch1、BF16全格点状态约为S **28.125MiB**、B **56.25MiB**；保存12层仅这些状态便约337.5／675MiB，还未含QKV、MLP中间量、梯度及teacher/学生双流。

跨窗精确缓存要求原帧、clip上下文、tubelet相位、空间crop、位置、padding和相关时间邻域一致。global中深层通常不满足简单跨窗复用条件。必须报告缓存建立、存储、读写、首窗、重置和命中率，不能把“重复帧”直接等同于“可免费复用深特征”。

# （f）Codex交接：先实现什么，怎样判断实现成立

完整接口、测试名和禁止混用的checkpoint合同已放入[实施交接](sandbox:/mnt/data/bmcr_review/CODEX_HANDOFF.zh.md)。最小改动集中在：

| 文件／符号                                                | 首要改动                                     |
| ---------------------------------------------------- | ---------------------------------------- |
| `full/scout.py::condition`                           | 精确向量化；保留伙伴、tie、集合均值和梯度                   |
| `full/model.py::route/train_batch`、`full/utility.py` | 增加S0/S1实际变化、条件交换与组合交互审计                  |
| `ds3/auxiliary.py`                                   | 新增零末层ResidualCompletion，不覆盖旧H0定义         |
| `ds3/model.py::native/ClipEngine`                    | 固定route、插值/H0/残差切换、合法local cached mosaic |
| `ds3/losses.py`                                      | 新C2 mixed GT、正确语义KD、clip/depth条件效用       |
| `ds3/routes.py`                                      | 显式uniform prior、有效预算和覆盖，不依赖零logits       |
| 新 `ds3/global_engine.py`                             | 拆贵算子与TIA，scatter完整空间格后调用global Adapter   |
| `ds3/runtime.py`、训练／评估工具                             | 新recipe隔离；online/EMA读取；真实计数与分阶段timing    |

其中最容易出现新错误的是global执行：原Adapter已经返回`input + delta`，不能再次做`x + adapter(x)`；也不能把compact clips当成完整global序列。

应先验证全重门与原图一致、零残差回到Z24、local缓存与真实compact一致、global错误缓存被拒绝、短窗有效与物理计数正确、教师冻结但学生feature梯度存在、声明token数与实际执行相符。**这些仓库一致性测试尚未在本次实现或运行；已通过的只有交付包中的独立CPU机制检验。**

扩大实验的依据应是：初始函数和执行图可信；条件效用确实预测混合状态收益；短动作、边界、严格tIoU没有被平均分掩盖的退化；实际成本改善超过运行波动。若失败，按证据改变相应因素，而不是自动增加训练长度或模块数量。

---

## 最终选择

在现有200/211、S/B和4090条件下，我最赞成的顺序是：

**修正BMCR完成同配方对照 → 同checkpoint四格诊断 → U24稳定残差C2 → 有证据后进入全时间状态＋条件贵更新。**

这条顺序既不放弃旧BMCR在B上的最好成绩，也不把完整clip提前排除；它先解决“弱状态替换强状态”和“训练没见过真实混合输出”的问题，再讨论更激进的三维去冗余。

三维压缩应共同保护三个对象：**视觉证据、物理时间几何、已学到的任务表示**。短动作不可观测、低分辨率丢失小物体、路由漏掉重复事件、global状态近似误差、teacher偏差以及小数据优化风险仍不能承诺消除。新的精度保持与端到端加速，需要在同一真实模型上共同验证，而不能分别从不同路线的最好数字拼接出来。
